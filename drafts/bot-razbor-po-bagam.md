## Подхват: когда к человеку подключается менеджер

Бот решает вопросы сам; менеджер подхватывает только застрявших. Тикет — только на подтверждённый баг.

| Признак «застрял» | Окно | Что делает система |
|---|---|---|
| Спросил одно и то же 2+ раза | сразу | отметка в карточке «нужен человек: повтор» |
| Бот ответил «не знаю / в доках нет» | сразу | «нужен человек: нет ответа» |
| Одна и та же ошибка у клиента 2+ раза | сразу | «нужен человек: ошибка» |
| Назвал команду, объём, тариф или спросил про оплату — и замолчал | 24 ч | «нужен человек: готов купить» |
| Лицензия есть, сервера нет | 3 дня | «нужен человек: не поставил» |
| Сервер стоит, подарок кончается | за 7 дней | «нужен человек: подарок кончается» |

Каждое утро — один список «кого подхватить» с причиной и ссылкой; менеджер пишет со своего аккаунта. Баг, который менеджер подтвердил, — в тикет. Так разработка получает только настоящие ошибки, клиент решает простое сам, а застрявшего подхватывают.

# Разбор по каждому сбою: что, почему, чем вредит продажам, как чинить

## Главное — три корня, из которых растёт почти всё

1. **Ответы команды не доходят до бота.** Владелец и admin отвечают на вопрос клиента в тикете — ответ уходит этому клиенту и остаётся в тикете. В базу бота он не попадает: база = доки + вшитые вводные, пересборка руками (видно в задачах: DEV-2671). Отсюда сбои №3, 5, 11 и половина «не знаю».
2. **У бота нет продажного режима.** Он сделан как саппорт: ответить по докам, завести тикет по «да». Нет правил: чем заканчивать ответ, когда отдавать человеку, когда дожимать. Отсюда №1, 2, 4, 6.
3. **У продажных заявок нет хозяина.** Все 175 карточек SALES на «Инге» (боте), 165 в стадии New. Тикеты SUPPORT разбирает диспетчер разработки. Человек по продажам в цепочке не стоит. Отсюда №1, 4, 6.

## 1. Просит человека или созвон — тикет без срока
- **Что:** SALES-118 — 12 раз «что ответили?» за два дня; SALES-90, 126 — просили онбординг, созвона нет; SALES-120 — бот пообещал человека и не завёл обращение.
- **Почему:** тикет — только по «да» клиента (решение владельца 14.07); тикет уходит в очередь разработки, не продажам; бот не видел статус (частично починено к 24.09).
- **Чем вредит:** просьба человека — самый тёплый сигнал. Мы отвечаем на него ожиданием без срока.
- **Решение:** продажные заявки (человек, команда, сделка) — сразу менеджеру без «да» (вопрос владельцу); у заявки срок ответа, который ты утвердишь; бот на «что ответили?» показывает статус и дату.
- **Кто:** владелец — правило; DEV — маршрут и статус; ты — срок.

## 2. Скидка, команда, объём — «не уполномочен»

- **Кто:** DEV.

# Метки и поля в Ю-треке: почему не работают и что сделать

**Что есть сейчас** (SALES, 175 карточек, 09.10):
- метка в трекере одна — «Звезда», не стоит ни на одной карточке;
- поля `pql`, `vertical`, `scale`, `tier`, `nurture_due` — пустые во всех 175;
- `State`: New — 165, Won — 9, Lost — 1: стадия не двигается;
- `subscription: paid` стоит у 51 карточки — при одной реальной оплате; поле значит не «платит», фильтр по нему врёт (что именно оно значит — уточнить у разработки).

**Почему не работают:** их должен ставить человек руками, а человека в цепочке нет. Метка, которую надо помнить поставить, не ставится никогда.

**Зачем вообще фильтры** — только под ежедневное действие. Если фильтр никто не открывает каждое утро, метка не нужна. Три действия, под которые они нужны:
1. **«Кому писать сегодня»** — сервер стоит, не платит; подарок кончается; лид замолчал после вопроса.
2. **«Заявки без ответа»** — сделка / партнёрство / просит человека, ответа нет.
3. **«Что мешает купить»** — причины отказа списком для владельца и разработки.

**Решение: не метки руками, а поля, которые ставит бот и синхронизация с админкой:**

| Поле | Значения | Кто ставит | Для чего |
|---|---|---|---|
| Стадия (вместо `State`) | регистрация / лицензия / сервер / оплатил / отказ | синхронизация с админкой раз в день | фильтр 1 |
| Тип запроса | поддержка / сделка / партнёрство / деньги / доверие / жалоба | бот, когда заводит заявку | фильтр 2 |
| Причина отказа | дорого / нет сервера / нет нужной функции / оплата не криптой / молчит | бот или менеджер при отказе | фильтр 3 |
| Следующее касание (`nurture_due`) | дата | бот, когда задал вопрос | фильтр 1 |
| Вертикаль, размер команды (`vertical`, `scale`) | гембла / нутра / другое; соло / 2–10 / 10+ | бот из ответа клиента | выбор тарифа, сегменты касаний |

Метка «партнёрство» отдельно не нужна — это значение поля «Тип запроса».
Три сохранённых фильтра в Ю-треке под три действия — один раз, руками.
