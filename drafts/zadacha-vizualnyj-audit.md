# Задача: Визуальный аудит сервиса — интуитивность и дизайн

Проект: MARKETING (или OP — на выбор). Держатель: Анастасия.

---

## Тело задачи

**Регулярный визуальный аудит продукта: как сервис работает глазами нового
пользователя, где интуитивно непонятно, что с дизайном.**

Зачем: продукт продаёт себя сам (product-led) — бесплатный месяц на своих
данных и есть главная витрина. Каждое место, где новый человек застревает
или не понимает, что нажать, — это потерянная оплата, которую не видно в
отчётах. Продукт и разработка — зона фаундера и dev-команды; эта задача
даёт им пользовательскую перспективу со стороны продаж, решения по
изменениям — за ними.

Как ведём:

1. Раз в неделю — проход одного раздела продукта глазами нового
   пользователя (порядок: онбординг после регистрации → установка
   лицензии → трекер → PWA-конструктор → Бритва → командный слой).
2. Каждая находка — строкой в комментарий задачи: **экран → что непонятно
   или мешает → предложение**. Скриншот прилагается.
3. Раз в месяц — свод для разработки: топ-5 находок по влиянию на путь
   к оплате, отдаются задачами в DEV.
4. Отдельно копятся дизайн-замечания (несостыковки стилей, мелкие
   визуальные баги) — пачкой, не по одной.

Первый проход: онбординг нового пользователя от регистрации до
установленной лицензии — ровно тот отрезок, где сейчас теряется половина
регистраций (43 из 88 без лицензии на 07.09, по админке).

## Примечание для себя (не в задачу)

- Находки про «фичи нет» сначала проверять через User Scripts/обработчики
  (правило из базы знаний) — половина «нехваток» закрывается скриптами.
- Свод для дева — через Клода: собрать, отжать, оформить.
