# CAC: как считать, где хранить, что просить у разработки

Черновик к обсуждению. Ничего не заведено.

## Часть 1. Что можно посчитать уже сейчас

Данные есть, просто лежат в разных местах. Затраты — в `MARKETING-63`
(сводка размещений Фазы 1), результат — в проекте `SALES`.

**Затраты на посевы, июль 2026** — 7 публикаций, **$4 172**, ≈46,2K просмотров:

| Канал | Реф-код | Оплачено |
|---|---|---|
| .Aff Inside | AFFINSIDE | $1 222 |
| iGaming News | IGAMINGNEWS | $900 |
| Pacan (пакет +2) | PACAN | $500 |
| adhunt | ADHUNT | $500 |
| FB-killa | FBKILLA | $490 |
| CPAGRAM (пакет +7) | **без метки** | $280 |
| Zombie Traffic | ZOMBIE | $280 |

**Результат июльской когорты** (лиды, заведённые в июле):
- лидов — 91
- с отметкой платной подписки — 28
- доведено до Won — 6

**Отсюда blended CAC по когорте июля:**

| Метрика | Расчёт | Значение |
|---|---|---|
| Стоимость лида | 4 172 / 91 | **≈ $46** |
| Стоимость платящего | 4 172 / 28 | **≈ $149** |
| Стоимость закрытой сделки | 4 172 / 6 | **≈ $695** |

**Это укладывается в целевой CAC ≤ $1 200** из внутренней модели компании
(`MARKETING-38`) с запасом почти вдвое даже по самой строгой метрике.

**Четыре оговорки, без которых число некорректно:**
1. Это **blended** CAC — всё поделено на всё. Разложить по каналам нельзя:
   в карточках `SALES` нет поля канала, привязка лида к реф-коду нигде не
   сохраняется.
2. `CPAGRAM` ($280) вышел с голым `qubix.pro` без реф-метки — эти переходы
   не атрибутируются в принципе.
3. Часть лидов пришла не с посевов (органика, прямые заходы, сарафан) —
   значит настоящий CAC по платному каналу **выше** расчётного.
4. Июльские посевы прошли 03–10.07, то есть **до начала испытательного
   срока** (27.07). Как затраты периода в отчёт за месяц 1 они не входят;
   это оценка эффективности вложения, а не расход месяца.

## Часть 2. Что мешает считать честно

Три источника данных, и один отсутствует полностью.

| Что нужно | Где сейчас | Состояние |
|---|---|---|
| Затраты по каналу и периоду | нигде | **отсутствует**, ведётся вручную вне систем |
| Привязка лид → канал | `?r=КОД` → кука → регистрация | технически есть, в карточку `SALES` не попадает |
| Оплаты по клиенту | биллинг | есть, сведено в `DEV-2167` |

Это зафиксировано при приёмке `DEV-2167` дословно: стоимости закупки
размещений по каналам в `admin.qubix.pro` нет ни в каком виде.

## Часть 3. Что просить у разработки

Предлагаемая задача в `DEV`: **«Реестр затрат по каналам и расчёт CAC в
админке»**.

### Раздел «Затраты» в admin.qubix.pro

Строка реестра = одно размещение или обязательство:

| Поле | Содержание |
|---|---|
| Канал / площадка | название и ссылка |
| Тип | посев TG · YouTube · статья/PR · амбассадор · листинг · конференция |
| Период действия | дата выхода или срок для длящихся сделок |
| Сумма и валюта | с фиксацией курса на дату платежа |
| Реф-код | связка с атрибуцией |
| Ссылка на задачу | `MARKETING-N` / `CONTENT-N`, где лежит аппрув |
| Статус | план · согласовано · оплачено |

Ввод — руками и импортом CSV. Права — коммерческая команда пишет,
остальные читают.

### Связка атрибуции

`реф-код в затратах` → `реф-код визита` → `регистрация` → `оплата`.
Первое звено новое, остальные в продукте уже есть.

### Витрина CAC

Поверх `DEV-2167`, который уже даёт Sales и Revenue по каналу, добавить
столбец затрат и считать:

- **CAC на лид** — затраты / лиды по коду
- **CAC на регистрацию** — затраты / регистрации по коду
- **CAC на платящего** — затраты / платящие по коду ← главная метрика KPI
- **Blended CAC** — все затраты периода / все платящие, включая органику

### Окно атрибуции — важная деталь

Цикл сделки 30–45 дней (подарочный месяц плюс решение об оплате, зафиксировано
в брифе `MARKETING-78`). Значит **считать надо когортами, а не календарным
месяцем**: затраты августа дадут платящих в сентябре. Помесячное деление
«затраты августа / оплаты августа» даст бессмысленное число — в числителе одни
люди, в знаменателе другие.

Это же надо учитывать при постановке KPI: сделки третьего месяца
испытательного срока оплачиваются вложениями второго.

### Экспорт

Выгрузка CSV за период — чтобы отчётность собиралась без ручного сведения.

## Часть 4. Что делать, пока этого нет

Не ждать разработку. Завести реестр затрат **сразу**, в той же структуре, что
описана выше — тогда при появлении раздела в админке данные просто
импортируются, а не собираются заново по переписке.

Где вести: раздел **«Базы»** внутри самого Qubix. Это ровно тот сценарий, под
который он сделан, и заодно живой пример использования продукта своей же
командой.

Задним числом восстановить есть из чего: `MARKETING-63` даёт все семь
июльских размещений с суммами и кодами, `CONTENT-4` — план первой волны,
`MARKETING-77` и `MARKETING-82` — суммы по амбассадору и тестовому проливу.
