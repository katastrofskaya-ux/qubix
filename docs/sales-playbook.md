# Sales-плейбук и AI-агент продаж

Источник: MARKETING-16. Связано: боли → `positioning-and-icp.md`, воронка →
`user-journey-map.md`, позиционирование → `positioning-and-icp.md`.

## Модель продаж: product-led / low-touch на PQL

Основа — product-led growth + лёгкий sales-assist. PQL (product-qualified
lead) — ядро. При ~$6K ACV это нижняя кромка hybrid-motion; тяжёлые
enterprise-продажи ломают юнит-экономику. Sales-assist включается только на
PQL — когда человек уже пощупал ценность в продукте.

**Почему НЕ MEDDIC/MEDDPICC**: enterprise-фреймворк под сделки на 6-7 знаков
с комитетом ЛПР — оверкилл для соло-байеров/небольших команд при $6K ACV.

**Роль BANT**: только входной фильтр (отсечь нецелевых на входе), НЕ метод
ведения. Байеры не терпят «бантинга» (допроса).

**Фундамент уверенности продаж**: Qubix реально стоит дороже своей цены —
возражения снимаются легко, если продающий (человек или бот) понимает фичи +
боли + данные рынка. Уверенность — от понимания, не от трюков.

**ICP-фильтр**: клиент — тот, кому нужен трекер (платит за него где-то) ИЛИ
нужно PWA. Кто на полном самописе и доволен — не наш клиент, силы не тратим.

## Пять навыков AI sales-бота (архитектура для справки)

Бот — stateless OpenRouter-агент (модель Opus 4.8), состояние живёт в
YouTrack (проект SALES), не в LLM — поэтому масштабируется на много
параллельных диалогов.

1. **foundation** (always-on) — язык клиента, тон только на «вы», формат под
   Telegram (2-4 коротких предложения), честность (не выдумывать цифры/сроки),
   деньги/скидки — НЕ зона бота (эскалация к человеку), никогда не палить
   слежку за поведением пользователя («вижу, вы смотрели X» — недопустимо).
2. **buyer-pains** (always-on) — карта 8 канонических болей (см.
   `positioning-and-icp.md`) с углом давления для каждой.
3. **sales-manager** — лёгкая квалификация (максимум 1-2 вопроса, не допрос)
   + отработка возражений фактами. Главный next-step для не-поставивших
   инстанс — НЕ «оплати», а «поставьте бесплатно на месяц на свой сервер».
4. **support** — Q&A о продукте строго из документации (RAG по docs.qubix.pro),
   не выдумывать; для пре-сейла мягко ведёт к демо/установке.
5. **escalation** — тикет в YouTrack только с согласия пользователя, с
   возвратом номера тикета; сначала пробует решить сам.
6. **discounts** — скидка никогда не даётся просто так, только в обмен на
   вклад (реферал, промо в канале и т.п.) — принцип взаимности. Бот сам
   размер скидки не называет.

## Ведение по воронке (флаги-вехи, не линейная лестница)

Путь длиннее, чем «демо → оплата»: решение зреет, когда человек поставил
бесплатный Qubix на свой сервер на месяц и пощупал на своих данных. Войти
можно любой дверью. Полная схема триггеров и таймингов — `user-journey-map.md`.

## Жёсткие инварианты продаж (не нарушать)

- Не палить слежку за поведением на демо/лендинге/кабинете — это только
  внутренний сигнал.
- Деньги и продуктовые решения — НЕ решает бот/консультант без письменного
  одобрения компании (см. также `contract-and-nda-summary.md` — ограничение
  полномочий по договору).
- On-premise privacy = главный аргумент продажи. Что происходит внутри
  инстанса клиента — принципиально не отслеживается.
- Формальное «вы», серьёзный B2B-тон, без впаривания и давления.
- Честность: не выдумывать возможности продукта — только то, что реально
  есть (сверять с картой фичей).
