### 2.2. Состояние KPI

**Оговорка, которую нужно оставить дословно:**

> Sales, Revenue и CAC по договору считаются из платёжных и биллинговых
> систем компании. Доступа к ним у меня нет. Ниже — данные CRM (проект
> SALES) как рабочий срез для сверки, а не как расчёт KPI.

| Показатель (CRM, на 26.08) | Значение |
|---|---|
| Новых лидов заведено за период | 12 |
| Сделок закрыто (Won) за период | 3 — `SALES-98`, `SALES-138`, `SALES-150` |
| Всего карточек в CRM | 104 |
| С отметкой платной подписки | 32 |
| В статусе Won | 7 |

**Отметке платной подписки в карточках доверять нельзя, и это проверено.**
У 13 карточек есть авто-описание, собранное из Postgres `licensing`. Сверка
поля с ним дала 3 расхождения, все в сторону завышения:

| Карточка | Поле | Платёжные данные |
|---|---|---|
| `SALES-90` | `paid` | «нет ни лицензии, ни платежа», инстанс не установлен |
| `SALES-138` | `paid`, **Won** | Оплачен: нет, тариф — нет подписки |
| `SALES-150` | `paid`, **Won** | Оплачен: нет, тариф — нет подписки |

Две из трёх — карточки в статусе Won, то есть как минимум две из семи
закрытых сделок платёжными данными не подтверждаются.

**Подтверждено оплатой — 4 клиента**: `SALES-141` (pwa_team, активна до
03.09), `SALES-133` (pwa_enterprise, истекла 17.08), `SALES-125`
(pwa_enterprise, истекла 13.08), `SALES-121` (pwa_enterprise, истекла 03.08).
Остальные 25 карточек с отметкой `paid` не имеют авто-описания — проверить
их нечем до закрытия `DEV-2176`.

Отдельно: `SALES-140` — собственная тестовая регистрация, `SALES-48` —
внутренний домен компании. Обе помечены `paid` и в клиентские метрики
попадать не должны.

**Поэтому цифру «32 платящих» в этом отчёте я не привожу как факт.** Дать её
компании — значит заявить результат, который не сойдётся с биллингом.
Достоверная часть: 4 подтверждённых клиента, из них активен на 26.08 один.

**Три вещи, которые нужно назвать прямо:**

1. **Данные CRM по оплатам недостоверны, и это установлено проверкой.**
   Поле подписки в карточках расходится с платёжными данными в трёх случаях
   из тринадцати проверяемых, включая две карточки в статусе Won. У 91
   карточки из 104 авто-описания нет вовсе, сверить их не с чем. Исправляется
   задачей `DEV-2176`, которая стоит из-за `DEV-2166` (в помехе с 22.08).
   До её закрытия любые цифры продаж из CRM — оценочные.
2. **CAC: расчёт по когорте есть, разбивки по каналам нет.**
   Июльские посевы — 7 публикаций на **$4 172** (`MARKETING-63`). Июльская
   когорта дала 91 лид, 28 с платной подпиской, 6 доведено до Won. Отсюда:

   | Метрика | Значение | Достоверность |
   |---|---|---|
   | Стоимость лида | ≈ $46 | надёжно — лиды считаются по факту заведения карточки |
   | Стоимость платящего | ≈ $149 | **условно** — знаменатель взят из поля, которому нельзя верить (см. выше) |
   | Стоимость закрытой сделки | ≈ $695 | **условно** — две из семи Won не подтверждены оплатой |

   Надёжна пока только стоимость лида. Две другие метрики станут
   достоверными после `DEV-2176`. Даже при худшем сценарии — если
   подтвердятся лишь 4 оплаты из 32 — стоимость платящего составит ≈$1 043,
   что всё ещё **укладывается в целевой CAC ≤ $1 200**.

   Оговорки: расчёт blended, разложить по каналам нельзя — в карточках
   `SALES` нет поля канала; `CPAGRAM` ($280) вышел без реф-метки и не
   атрибутируется вовсе; часть лидов пришла не с посевов, значит реальный
   CAC платного канала выше. Посевы прошли 03–10.07, то есть до начала
   испытательного срока — это оценка эффективности вложения, а не расход
   отчётного месяца.

   Причина, по которой нет разбивки по каналам, не организационная:
   стоимости закупки размещений не ведутся ни в `admin.qubix.pro`, ни в
   какой-либо другой системе компании — зафиксировано в описании `DEV-2167`
   при приёмке. Методика расчёта, структура реестра затрат и постановка
   задачи разработке — отдельным документом (см. предложение по CAC).
3. **Месяц 1 пришёлся на подготовку к релизу, который сдвинулся.** Первая
   волна посевов подготовлена, но не запущена — сознательно, чтобы не вести
   платный трафик на старое позиционирование. Соответственно поток лидов в

**Справочно** (из брифа `MARKETING-78`): средний чек $439 с клиента за месяц,
цикл сделки 30–45 дней с учётом подарочного месяца.
