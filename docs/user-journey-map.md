# User Journey Map — воронка как набор вех-флагов

Источник: MARKETING-14. Связано: боли → `positioning-and-icp.md`, метрики →
MARKETING-15, sales → `sales-playbook.md`.

## Суть в одном абзаце

Путь пользователя — не линейная воронка-лестница, а набор булевых вех-флагов
на лиде (можно войти с любой двери: демо-без-рега, рег-без-демо и т.д.).
Между «зашёл в демо» и «оплатил» лежит ключевая стадия — **бесплатный
self-host инстанс на месяц**, в которой и зреет решение о покупке. После
установки инстанс принципиально не отслеживается (on-prem privacy — это
проданная ценность, а не ограничение); тайминг follow-up берётся только из
лицензионных логов (heartbeat + дата истечения триала).

## Вехи и что делать на каждой

| Веха | Что делаем |
|---|---|
| Узнал (pre-contact, лендинг) | Ещё нет контакта — только собираем сигнал (что зацепило), чтобы персонализировать первый разговор при заходе в бота. |
| Зашёл в демо, не зарегистрирован | Вести к регистрации. |
| Зарегистрирован, демо не видел, не поставил | Толкать к установке инстанса (можно мягко предложить демо). |
| Зарегистрирован, был в демо, не поставил | Довести до установки бесплатного инстанса на свой сервер — **главный next-step, не «оплати»**. |
| Поставил (первый heartbeat) — поворотная веха | +1 день: вежливый чек-ин-забота «как встало, нужна ли помощь» (НЕ продавать, не спалить слежку). В течение месяца — не мешать, помогать по запросу. |
| Близко к истечению триала | Главный дожим, заблаговременно, в будни, в местном времени клиента — спокойно спросить впечатления + дать путь оплаты, без давления. |
| Триал истёк без оплаты | Мягкий win-back. |
| Оплатил | Продажный дожим выключается → onboarding/support/upsell. |

## Модель PQL (product-qualified lead)

Value-столпы (касание любого = сигнал ценности), по приоритету:
1. AI-first (главный)
2. Автоправила (Britva) — авто-пауза убыточных
3. Трекер/аналитика (ROAS)
4. PWA-платформа
5. FB-парсер без банов

Правило: **Hot** (→ sales-assist) — коснулся ≥2 столпов ИЛИ вернулся
повторной сессией; **Warm** (self-serve) — коснулся 1 столпа; **Cold** —
демо-визит без касания ценности. Демо-PQL — это до-триальный сигнал
(определяет, насколько активно толкать к установке); после установки
поведение внутри инстанса уже не скорим (не видим).

## Правила проактивных касаний

Структура [повод] → [вопрос]. Жёстко нельзя: пугать (loss-aversion),
презюмировать использование/результаты (on-prem — не видим), впаривать,
повторять один и тот же вопрос между касаниями. Эскалация наружу — только с
согласия пользователя, с возвратом номера тикета.

## Три поверхности замера

1. **Лендинг** (qubix.pro) — rrweb-запись анонимной сессии → тепловая карта,
   pre-contact intent (что зацепило ещё до контакта).
2. **Демо** (demo.qubix.pro) — события уже пишутся (page-level, план —
   апгрейд до кликов+rrweb); PQL-скоринг по value-столпам.
3. **Кабинет** (my.qubix.pro) — смотрел тарифы, дошёл до оплаты.

Сигнал всегда внутренний — наружу не озвучивается («вижу, вы смотрели X» —
жёсткий запрет).
