# Tone of Voice и правила копирайтинга

Источник: MARKETING-9. **Обязательный бриф для любого автора текста** —
лендинг, реклама, статья для медиа, кабинет, документация.

## Главный принцип: Benefits sell, features tell

Маркетинговый текст ПРОДАЁТ. Не документация, не спека. Правда = продукт
(не выдумывать), но подача = маркетинг. Байер не покупает «движок на JS» —
он покупает избавление от конкретной боли. Фича — доказательство (proof),
что боль закрыта. Если ловишь себя на «перечислю фичи» или «напишу, чего в
продукте нет» — стоп, это спека, а не продажа.

## Голос и адрес

| Поверхность | Адрес | Тон |
|---|---|---|
| Лендинг (qubix.pro) | «вы» | профессионально, продающе |
| Кабинет (my.qubix.pro) | «вы» | профессионально |
| Документация (docs.qubix.pro) | «вы», безлично | нейтрально, без маркетинга |
| In-product UI | «вы» | профессионально |
| Реклама / email | «вы» | продающе |
| Нативная реклама в голосе TG-канала | «ты» (осознанное исключение) | как голос канала |

Правило Qubix: серьёзный on-premise продукт — формальное «вы», без
панибратства, «ты» никогда в продуктовых поверхностях (единственное
исключение — речь автора TG-канала внутри рекламного размещения).

## Железные правила подачи

1. **Позитивный фрейминг** — не «без Redis», а «лёгкий стек, летает на
   дешёвом VPS». Слова нет/без/никаких/не нужно отпугивают даже внутри
   «выгодных» фраз. Исключение — прямой ответ на вопрос («Нужно ли X?» →
   «Нет.») это не запретное отрицание, а ответ.
2. **Ноль внутреннего жаргона** — байер не разработчик. Термин уровня байера
   (постбэк, гео, анти-детект, CAPI, PWA, ROAS) — ок; имена таблиц/движков/
   «дедуп»/`event_id` — нет.
3. **Боль — завуалированно**, не в лоб («Боль: X. Решение: Y» — плохо;
   вопрос-забота «нужно ли постоянно X?» — хорошо).
4. **FAQ на лендинге = снятие возражений**, не техническая справка (справке
   место в докax). Каждый вопрос — реальное возражение байера, ответ —
   как Qubix его снимает + proof.
5. **Правда = продукт** — не обещать того, чего нет в коде. Цифры реальные.
6. **Вопросы рождаются из умной фичи**, не из тупой подстановки боли в
   вопрос — заходить сбоку, через неочевидную возможность.
7. **Развей известные страхи рынка прямо** (например, «за парсинг банят») —
   не обходи молчанием, разверни уверенно с деталями.
8. **Конкуренты — только контекст для автора**, в клиентский текст их не
   пишем.
9. **По одному Q&A за раз при согласовании** с заказчиком — не вываливать
   списком на 10 вопросов.

## Фреймворки

- **PAS** (Problem → Agitate → Solution) — для блока про конкретную боль и
  FAQ-ответа.
- **BAB** (Before → After → Bridge) — для пиллара/секции.
- **FAB** (Feature → Advantage → Benefit) — дотягивать фичу до выгоды; в
  тексте оставлять benefit, фичу — как доказательство.
- **4P** (Promise → Picture → Proof → Push) — для героя/финального CTA.

Гибридизировать, не лупить один шаблон везде.

## Voice of customer

Брать слова байера («связки», «залив», «гео», «деп», «выгорает», «кабинет
улетел», «домен сгорел»), а не корпоративные («оптимизируйте конверсионную
воронку» — мимо).

## Эмодзи и формат для Telegram

Эмодзи — варьированные, не монотонные (не сыпать одинаковыми подряд).
Воздух между блоками — пустые строки, не лепить стену текста.

## Документация (отдельные правила для docs.qubix.pro)

- **Ноль фантазии** — писать только то, что лично проверено в коде/UI.
  Не можешь проверить — не выдумывай, оставляй явный плейсхолдер.
- Для пользователя, не для разработчика — ноль внутренних терминов.
- Формальное «вы», безлично, никогда «ты», без разговорного тона.
- Ноль ИИ-сленга и калек-несловов (транслит-уродцы типа «фунл», casual-жаргон
  «умная фича», бессмысленные мета-пояснения).
- Избегать англицизмов, где есть живое русское слово («фича»→возможность,
  «юзер»→пользователь, «деплой»→установка); исключение — устоявшиеся термины
  без нормального эквивалента (PWA, ROAS, CTR, API, постбек).
- Апрув текстов до записи — для нового user-facing контента показать ключевые
  строки заказчику.
- Буква ё — писать (не ронять в «е»).

## Red flags — «стоп, ты пишешь спеку, а не продаёшь»

- В строке есть без/нет/никаких/не нужно → переформулировать через выгоду.
- Назвал фичу и не дотянул до выгоды байера.
- Внутренний термин в видимом тексте.
- Боль написана в лоб вместо вуали.
- FAQ-вопрос объясняет «как устроено» вместо «снимает возражение».
- Перечисляешь, чего в продукте нет, чтобы выглядеть круто.
- Несколько близких вопросов вместо одного.
